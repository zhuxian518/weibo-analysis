## 两类验收不要混淆

工程层看配置、请求、失败处理和文件保存；AI层看事实、证据、用户问题与创意。2026-10-20基线 `417fd5f` 的10项安全离线测试仅属于前者；后者按[AI评估](AI_EVALUATION.md)由人工执行并留证。

## 口径、样本与采集

| 指标 | 分子 / 分母 | 拟采集方法与建议门槛 |
| --- | --- | --- |
| 可核验事实覆盖 | 有有效证据且支持原意的关键事实条数 / 全部关键事实条数 | 两名评审按证据包逐条核对；试点目标≥90%，零事实标不适用，不伪报100% |
| 无依据事实率 | 无来源支持或被证据否定的事实条数 / 全部关键事实条数 | 保留所有未入选输出；建议≤5%，严重捏造一条即阻断对外报告 |
| 任务可用率 | 评审认为可进入下一轮验证的报告数 / 所有提交评估的报告数 | 分母含失败/空报告；门槛待首轮基线后确定，不能只评高分入选创意 |
| 创意可行动性 | 同时有具体用户/问题/最小验证动作的创意数 / 全部生成创意数 | 双人独立评分；建议先看逐项缺失，再决定是否改prompt |
| 用户理解 | 能正确指出事实、推断和未验证假设的人数 / 看过同一报告的参与人数 | 先做3人可用性观察，报告原始人数；目标3/3仅作问题排查 |
| 完成时间 | 从收到固定材料到完成选题判断的分钟数 | 记录全部开始者；中止另列，不把未完成者删掉；没有旧流程基线不声称节省X% |
| 人工返工 | 必须改写的关键事实/创意数 / 全部评审条目数 | 分类记来源、错误、重复、空泛；不以模型自评分替代 |
| 安全与成本护栏 | 凭据泄露、注入执行、未转义危险内容计数；实际调用次数/费用 | 建议严重安全事件0；调用费用未知则标未知，不估成已消耗 |

关键事实指会改变事件解释、用户问题或创意可行性的外部断言，评审先冻结标注规则。相同事实重复表达去重计数，但错误传播位置保留。每个报告先按案例统计，再汇总，避免长报告支配全部比例。

## 分阶段样本计划

1. 从[8条合成案例](evaluation-cases.csv)开始，仅检验流程与边界，不代表真实微博分布。
2. 待获得授权后再补真实、去敏、带采集日期的证据包；覆盖普通/缺源/冲突/敏感话题，记录抽样和排除，数量另定。
3. 固定宿主、模型版本、提示、工具权限与采样参数，记录失败与重试；同输入至少重复两次才能初步看稳定性，不能据此给统计显著性。
4. 3名假设目标用户完成同一报告阅读任务；仅发现可用性问题，不当作市场验证或总体接受率。

若比较现有提示与修订提示，用同证据包、随机匿名顺序、相同评审；未完成A/B执行前不写“提升”。本轮不修改Skill或80/20权重，改进仅写建议。
